Revamping view_edit_solution

Three interactive mockups using the real Bootstrap theme and dummy data (42 students, 11 rooms, a 16-room hotel). All three share the same in-browser state, so edits made in one appear in the others. Use Reset demo data in the navbar to start over.

AWorkbench

The current page, rebuilt: every room at once, with much better feedback.

  • Live stats bar that previews the change while you drag
  • Threads from the dragged student to everyone they requested or were requested by, colored by whether the drop would satisfy them
  • Every room shows a delta badge during a drag; the best targets glow
  • Drop on a student to swap; Unplaced pool for parking students
  • Inspector with live "best moves and swaps"
  • Inline hotel-room renaming, capacity beds, undo/redo, activity log
Try: hover a chip to see its threads, then drag Sofia M. around and watch the badges. Click a red chip and use a suggested swap.

BHotel placement

A second step for the "place into real hotel rooms" job. You drag whole groups, not students.

  • Floor plan with room numbers, bed counts, chaperone-blocked rooms
  • Connecting doors show how many requests cross between the two groups
  • Dragging a group draws affinity threads (thickness = request count) to the groups it is linked to, and marks which tiles fit
  • Suggest placement puts the most-linked groups behind connecting doors
  • Roster view with a print stylesheet (the current page lost its print view)

CFix-it queue

A guided alternative to scanning a big grid: one problem at a time.

  • A queue of issues: broken hard rules, nothing granted, "not with" broken, optionally "only 1 granted"
  • Shows only the rooms involved for the student in focus
  • Top 4 options with side effects ("Priya 1→0, none!")
  • Hover an option to preview it in place: chips ghost into the new room and threads recolor
  • Keyboard driven (J/K, 1–4), and moves to the next issue on its own

Shared ideas across all three

  • Chip status replaces the cryptic (x|y) counts. Pips show requests met, and colors mean: all met (green), none met (red), broke a hard rule (solid red), made no requests (dashed gray, which today is wrongly shown red).
  • Thread language: solid = they requested, dashed = requested them, green = met, coral = not met, dark red = hard rule broken, orange dotted = "not with" broken, animated = unknown (someone is unplaced).
  • Manual forbid/require rules are finally visible. Today they only show up as a +1,000,000 jump in the score.
  • Undo/redo (⌘Z/⇧⌘Z) and a change log, while still editing in place.
  • A workflow: A or C to fine-tune students, then B to place groups into hotel rooms and print.

What this would mean for the backend

  • Client-side scoring. Live previews need the request graph on the page (one JSON blob). shared/engine.js ports evaluate.py; one score function should be the source of truth, or the server should stay authoritative and the client only preview.
  • Endpoints: a swap endpoint (two moves today means two re-evaluations). move should return the new stats directly so the page doesn't make a second reevaluate call, and rename should go through AJAX instead of a full form POST and reload.
  • Hotel inventory doesn't exist yet. Site.room_desc blocks only store counts and capacities. B needs room numbers, beds, connecting pairs and blocked rooms, probably a HotelRoom model per Site, with Room.placed_name becoming a foreign key.
  • Unplaced pool: students in no Room. evaluate.py already skips them; the page needs to list them.
  • Undo: client-side is enough for a mockup; a small SolutionEdit log table would make it survive a reload.

Existing issues spotted along the way

  • reevaluate_solution has no @login_required, so anyone can read student names and scores. move_student_in_solution is @csrf_exempt.
  • evaluate.py counts repel requests in num_reqs but never as successes or failures, which skews the ratio and can hide "nothing granted" students.
  • The badge counts and the student modal treat repel requests as wishes to room together.
  • admin_solution_edit.html (the old template) is dead code.
